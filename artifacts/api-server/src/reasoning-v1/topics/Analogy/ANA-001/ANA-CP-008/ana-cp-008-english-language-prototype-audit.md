# ANA-CP-008 English Language Prototype Audit

Status: **NON-QL LANGUAGE PROTOTYPE — EDITORIAL DISCOVERY**

## 1. Purpose

This stage converts the green ANA-CP-008 operation inventory into student-facing English prototypes without assigning permanent QL IDs or freezing a template count.

The prototypes test whether each distinct operation can support natural exam-style wording, value-specific explanations, realistic misconception rejection, and correct cluster-first or number-first rendering.

The prototype inventory is a design probe, not a permanent manifest.

## 2. Current candidate language boundaries

The prototype layer currently represents:

- ordinary-position sum to number;
- ordinary-position product to number;
- position sum mapped back to a letter;
- single-letter position square;
- independent letter shift plus whole-number delta;
- one shared cluster/number delta;
- independent two-letter vector plus numeric delta;
- exact multiplier in cluster-first order;
- exact multiplier in number-first order;
- direct cube;
- perfect-square-to-cube;
- exact cube root after adding one;
- exact square root after adding one in number-first order;
- digit-sum-square successor.

These are candidate language boundaries. They do not imply the final QL count because boundaries may merge or split after multilingual, source, misconception, and bridge review.

## 3. Student-facing task eligibility

### Direct completion

Prototype form:

```text
Choose the term that completes the analogy: SOURCE : RESULT :: TARGET : ?
```

Instruction wording varies while the task contract remains stable.

### Odd/incorrect pair selection

Prototype form:

```text
Three of the following pairs follow the same relationship. Select the pair that does not belong to the group.
```

For every candidate family:

- three pairs are generated by the intended rule/context;
- one pair uses the same input and a plausible nearby wrong output;
- the first three pairs uniquely identify the intended context;
- the odd pair does not follow that context;
- all four pair options are canonically unique.

### Deferred tasks

Equivalent-pair selection remains mechanically viable but is not allocated here because an exact official mixed-pair fixture is still pending. Inverse and double-missing mixed tasks remain unsourced.

## 4. Explanation contract

Every direct prototype returns:

```ts
{
  ruleStatement,
  sourceDemonstration,
  targetApplication,
  conclusion,
  closestTrapRejection
}
```

The rule statement describes the student operation without internal IDs. The source and target demonstrations use the actual displayed values. The conclusion names the generated answer. The nearest-trap rejection explains a plausible misconception in teacher-style language.

## 5. Composite explanation requirements

### Independent letter-number transform

Must show the letter shift and whole-number operation separately and state that they are independent.

### Shared cluster-number delta

Must show that one signed value applies to the first letter, second letter, and whole number.

### Independent vector

Must show each positional letter change separately and then the numeric delta.

### Exact multiplier

Must show exact arithmetic:

```text
input × numerator ÷ denominator = output
```

Rounding or decimal approximation is prohibited.

### Direct cube

Must distinguish cubing from multiplying by three or squaring.

### Perfect-square-to-cube

Must show both stages:

```text
n = r²
r³ = output
```

### Successor roots

Must show:

```text
n + 1 = perfect square/cube
exact root = output
```

Approximate roots are prohibited.

### Digit-sum-square successor

Must verify the attached input letter and recompute the output letter from the incremented number. It must not describe a fixed letter shift.

## 6. Token-order audit

Cluster-first answers retain:

```text
LETTERS + SIGNED_NUMBER
```

Examples include `GD10`, `NF-5`, and `QI11`.

Number-first answers retain:

```text
SIGNED_NUMBER + LETTERS
```

Examples include `156BY` and `11OJ`.

Correct components in the wrong order are not equivalent answers.

## 7. Mechanical editorial tests

`provisional-language-templates.en.test.ts` requires:

- unique prototype identifiers that are not QL IDs;
- representation of every provisional runtime authority;
- separate candidate coverage for sum/product and direct-cube/square-to-cube boundaries;
- four unique sample inputs per prototype;
- rule-authority and independent-solver agreement;
- unique intended context ownership;
- correct direct answer type;
- four unique odd-pair options;
- exactly three valid pairs and one invalid pair;
- no internal IDs or implementation vocabulary in student text;
- no unresolved placeholders;
- no compressed answer-key language;
- actual source and target values in explanations;
- operation-specific nearest-trap rejection;
- no exact duplicate source demonstrations;
- no exact duplicate target applications;
- number-first and cluster-first order preservation;
- zero permanent QL IDs;
- `publiclyPublishable: false`.

## 8. Current exclusions

The prototype layer does not admit:

- equivalent-pair permanent allocation;
- inverse completion;
- double-missing completion;
- reverse-position aggregates;
- generic letter-gap/difference rules;
- generic number-to-letter coding;
- meaningful-word value rules;
- Coding-Decoding grammar;
- CP-009 pair-index progression.
