## Candidate merge 1 — interleaved cluster series

```text
TWO_INTERLEAVED_CLUSTER_SERIES
K_INTERLEAVED_CLUSTER_SERIES
  -> INTERLEAVED_CLUSTER_SERIES
```

### Shared invariant

Displayed terms are partitioned by position modulo `rowCount`; each row continues independently.

```text
rowCount = 2   odd/even rows
rowCount = 3   positions 1,4,7...; 2,5,8...; 3,6,9...
rowCount = 4   positions 1,5,9... and so on
```

### Why a merge is plausible

- Both current authorities use `INTERLEAVED_ROWS` as the learner proof model.
- Task direction does not change the reasoning contract.
- `rowCount` is an instance parameter, not a new mathematical operation.
- The combined candidate contains 17 temporary templates.

### Risk to review

Two-row odd/even series are much more common and easier to detect than three- or four-row forms. The final runtime may keep a specialized two-row explanation and difficulty calibration even if the permanent authority is unified.

A merge must not flatten exam weighting or make four-row saturation probes appear as common source-backed questions.

## Candidate merge 2 — directional consecutive clusters

```text
VARIABLE_LENGTH_CONSECUTIVE_CLUSTER
GROWING_CONSECUTIVE_CLUSTER
  -> DIRECTIONAL_CONSECUTIVE_CLUSTER
```

### Shared invariant

Each term is a consecutive-letter group. Its length changes by a fixed signed delta while the next starting position follows a fixed gap rule.

```text
lengthDelta < 0   shrinking groups
lengthDelta > 0   growing groups
```

### Why a merge is plausible

- Both use `LENGTH_OR_CONTENT_CHANGE` as the learner proof model.
- Direction changes the parameter, not the solver.
- Refined English V2 already uses the same predecessor-to-answer evidence for both.
- The combined candidate contains 8 temporary templates.

### Risk to review

The current shrinking family blocks previous-term generation where hidden material may be underdetermined, while the growing family supports it. Recoverability must stay a template/task constraint and must not be inferred from the merged authority alone.

## Candidate merge 3 — periodic block completion

```text
REPEATED_BLOCK_COMPLETION
ALTERNATING_BLOCK_COMPLETION
  -> PERIODIC_BLOCK_COMPLETION
```

### Shared invariant

A continuous line is generated by a repeating cycle of one or more blocks; missing letters or groups are recovered after reconstructing the complete line.

```text
blockCycleLength = 1   one repeated block
blockCycleLength = 2   two alternating blocks
```

### Why a merge is plausible

- Both use `CONTINUOUS_GAP_COMPLETION` as the learner proof model.
- Flat missing-letter and grouped-gap answers are presentation semantics rather than new authorities.
- Disha source tracing already proved that blank layout alone cannot determine ownership.
- The combined candidate contains 8 temporary templates.

### Risk to review

The merged generator must preserve which block position supplies each blank. A generic periodic solver must not sort, flatten, or reorder grouped answers.

## Authorities deliberately not merged

### Cyclic versus general fixed permutation

```text
CYCLIC_CLUSTER_PERMUTATION
FIXED_POSITION_PERMUTATION_CLUSTER
```

Rotation is mathematically a fixed permutation, but the current split remains defensible because:

- cyclic rotation preserves relative order around a cycle;
- it is directly source-backed and common in exam material;
- the general fixed-permutation authority contains saturation-only pair swap, reversal and odd/even reorder probes;
- learner explanations and distractors differ materially.

This pair should be reconsidered only if the permanent QL policy treats all fixed permutations as one parameterized contract and preserves source-frequency weighting separately.

### Cumulative prefix versus patterned insertion

```text
CUMULATIVE_PREFIX_CLUSTER
PATTERNED_INTERIOR_INSERTION_GROWTH
```

Both grow, but cumulative prefix growth preserves a fixed boundary and appends to one side. Patterned insertion preserves the old sequence while inserting at changing interior positions. Their recovery and misconception models differ.

### Marker movement versus positional substitution

```text
MARKER_BLOCK_POSITION_SHIFT_OVER_PERIODIC_FRAME
PROGRESSIVE_POSITIONAL_SUBSTITUTION
```

The first moves a marker relative to a regenerated background. The second moves a source/target boundary by replacing one additional position. Wave E established these as distinct retained contracts.

### Fixed versus progressive column movement

The first repeats one position-wise step vector; the second changes the step itself according to a progression. They remain separate.

## Manual decision rubric

Approve a merge only when all are true:

1. The mathematical solve contract is one parameterized invariant.
2. Task direction and answer semantics remain properties, not separate logic.
3. One authority can support clear learner explanations without generic wording.
4. Distractors remain misconception-specific across the full parameter range.
5. Source-backed and saturation-only frequency can still be controlled independently.
6. Recoverability restrictions remain enforceable per template.
7. Analytics can still distinguish meaningful submodes through metadata.

Reject or defer a merge when any of these are false.
