## 1. Why sixteen prototypes become twenty-four solve contracts

The checkpoint has sixteen task-contract prototypes. Fourteen prototypes map to one provisional solve contract each. The two exact atomic prototypes each support five materially different proof topologies.

Those five exact topologies cannot remain one final solve mode merely because they share a generator:

- direct singleton intersection identifies one common word-token pair immediately;
- chained singleton propagation first resolves a helper pair and then removes it from later evidence;
- set-difference elimination subtracts a known overlap from another statement pair;
- forked evidence join combines two independent evidence branches;
- global bijection deduction requires the full one-to-one mapping constraint because no local singleton is sufficient.

Their correctness predicate and answer type are shared, but their student proof path, explanation obligation, inference burden and misconception structure are materially different. Because one final QL exposes one solve-mode identity, each topology survives separately in both query directions.

## 3. Final decisions by axis

| Axis | Decision | Executable reason |
|---|---|---|
| encode versus inverse decode | split | different answer domains, option pools, query language and inverse ambiguity gates |
| exact versus possible versus impossible | split | invariant proof, existence witness and universal exclusion are different predicates |
| atomic versus set answer | split | set canonicalisation, equality and distractor construction differ |
| ordinary exact versus missing-member presentation | split | blank reconstruction changes the payload and proof obligation |
| possible member versus complete candidate domain | split | one witnessed member is not the same answer as the entire candidate set |
| invariant ambiguous set versus resolved composition | split | one preserves internal ambiguity; the other proves components independently before composition |
| direct/chained/difference/forked/global exact topology | split | materially different student solve paths and explanation schemas |
| two-way versus three-way uncertainty | merge | candidate width changes instance difficulty but not the predicate or solver operation |
| statement count | merge | row count alone does not define a new reasoning operation |
| table/paragraph, quotation and row-order variants | merge | renderer variation only |
