**Checkpoint:** Number Sets, Order, Parity and Integer Structure  
**Status:** deliberately incomplete executable discovery

## 1. Purpose

Wave 1 is not a completeness claim. It proves that CP-001 can construct exact states, solve them canonically, verify them independently, build deterministic misconception-owned options, emit question-specific explanation evidence and remain completely delivery-locked while discovery continues.

## 3. Exact-state requirements

- All integer arithmetic is exact.
- Rational classification uses numerator/denominator structure; no floating-point equality decides rationality.
- Irrational foundation states are restricted to square roots of positive non-square integers.
- Interval counts have explicit lower/upper inclusion flags.
- Parity canonical routes use parity algebra while verifier routes evaluate bounded even/odd integer witnesses independently.
- Parity truth-class options are mutually exclusive: always true, true only for even `n`, true only for odd `n`, or never true.
- Consecutive reconstruction requires integer feasibility and verifier enumeration.
- Prime/composite truth-testing is not part of the Wave 1 learner contract; CP-004 retains that governing ownership.

## 4. Deterministic option policy

Every package has exactly four unique options and one correct option. Answer position is deterministically rotated across seeds. Wrong options are attached to a named misconception; no anonymous filler distractors are permitted.

Examples of owned distractor logic:

- choose a larger containing number set instead of the smallest applicable one;
- reverse negative-number order;
- use signed displacement instead of distance;
- count both interval endpoints regardless of openness;
- apply an incorrect sum/product/power parity rule;
- interchange the even-`n` and odd-`n` truth cases;
- shift a consecutive block or use spacing of 2 instead of 1.

Internal misconception IDs may be retained as reviewer metadata, but learner-facing explanations must render them as normal instructional language.

## 5. Difficulty contract

Difficulty labels are derived from reasoning state, not seed number or arithmetic magnitude alone.

Wave 1 uses examples such as:

- direct positive-number classification before representation-sensitive classification;
- shorter/simpler signed-order states before longer mixed-sign states;
- same-side number-line distance before opposite-side crossing-zero distance;
- closed intervals before half-open and open endpoint handling;
- direct parity rules before polynomial parity identities;
- 3-term consecutive reconstruction before 4- and 5-term reconstruction.

Each prototype must still reach EASY, MEDIUM and HARD during the proof sweep.

## 6. Explanation contract

Each generated package carries:

1. core concept;
2. given data and strategy;
3. numbered/ordered reasoning steps;
4. an exam-speed method;
5. three option-specific/common-trap notes in learner-facing prose;
6. final answer.

The explanation must be derived from the generated hidden state. Generic reusable paragraphs are insufficient. Learner-visible content must not expose internal enum labels, prototype IDs or raw misconception identifiers.

## 8. Proof sweep

The exact runtime proof will generate at least 100 seeds for each of the eight prototypes and require:

- deterministic replay equality;
- canonical/verifier agreement;
- four unique options with exactly one correct answer;
- every answer position reached by every prototype;
- EASY/MEDIUM/HARD reached by every prototype through reasoning-state calibration;
- multiple genuine mathematical fingerprints per prototype;
- required edge topology coverage;
- mutually exclusive learner-facing parity truth classes;
- zero learner-facing internal-label leakage;
- source and prototype ancestry present;
- zero lifecycle leakage.

A separate structural audit checks learner-facing rendered-question identity, internal-ID leakage, cross-prototype collisions, explanation/option integrity and learner-facing editorial text. A small review export is retained as human-review evidence.

## 9. Deliberate non-closure

Wave 1 does **not** close CP-001. Wave 2 must expand inverse/count/set/least-greatest directions. Wave 3 must add boundary and representation topologies. Wave 4 must saturate sources and recover legacy traces. Wave 5 performs merge/split and only then may a count-bearing ID-free template proposal be brought for product approval.
